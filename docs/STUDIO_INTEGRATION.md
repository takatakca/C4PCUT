# TAKATAK Studio integration boundary (proposed, not connected)
The current private owner editor has a local usage ledger. Do not embed it in the public Studio or pass browser-controlled client/workspace IDs into its trusted scope.

Required future contract: TAKATAK authenticates the user server-side, resolves workspace membership and active product entitlement from authoritative records, issues short-lived audience-bound credentials, and C4PCUT verifies identity, workspace and permission on every project/media/job access. Bind usage events to trusted workspace, operation ID and entitlement version. Reserve quota transactionally before dispatch; reconcile terminal outcomes with durable idempotency. Separate resource protection (attempt seconds) from any customer billable event. Never invoice cancelled or failed tasks merely from this local ledger. A verified Studio media authorization API, secure worker isolation, service-to-service transport, and explicit product/pricing approval are prerequisites. Do not accept arbitrary remote URLs or paths for media. No changes to takatak-v1 or live billing in this increment.

## Implemented private namespace precursor
Explicit workspace credentials now select a server-owned namespace, independent project map, per-workspace CSRF token and local usage ledger. No browser-provided workspace ID grants authority. Render status and cancellation check the authenticated workspace. This establishes an application-level isolation baseline for the later verified Studio credential exchange; it does not yet authenticate TAKATAK members or read Studio entitlements. Do not expose publicly or connect to live billing.

## Actual Studio pack interoperability
Verified TAKATAK v1 main at 09c6f21f42d0ee39385ec5e11c389fba6a191205. Its src/lib/studio/production.ts defines TAKATAKSTUDIO production_request_pack v1 and creative fields; src/app/api/studio/projects/route.ts requires create_content and derives clientId from authenticated access. C4PCUT accepts the same pack envelope and only whitelists title, brief, language, audience, and character names/profiles. Imported identities, jobs, billing, URLs and approvals do not confer authorization. The user attaches a local JSON pack to an existing source project and explicitly saves it; no automatic AI generation, publish, or payment. Director prompt is a creative suggestion; characters remain saved context but are not automatically sent to the model. No modifications to takatak-v1.

For future live SSO, reuse requireWorkspaceApiPermission("create_content") and studioEnabled on V1. A dedicated C4PCUT product entitlement check is still needed; do not reuse Social subscription/bypass as an authorization shortcut. A gateway must authenticate all media, session and job requests and bind the verified activeClientId to a server-managed workspace mapping, with short expiry, revocation and replay protection. Do not enable a public listener until reviewed. No issuer or live SSO is implemented here.
