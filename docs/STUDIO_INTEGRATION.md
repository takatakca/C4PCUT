# TAKATAK Studio integration boundary (proposed, not connected)
The current private owner editor has a local usage ledger. Do not embed it in the public Studio or pass browser-controlled client/workspace IDs into its trusted scope.

Required future contract: TAKATAK authenticates the user server-side, resolves workspace membership and active product entitlement from authoritative records, issues short-lived audience-bound credentials, and C4PCUT verifies identity, workspace and permission on every project/media/job access. Bind usage events to trusted workspace, operation ID and entitlement version. Reserve quota transactionally before dispatch; reconcile terminal outcomes with durable idempotency. Separate resource protection (attempt seconds) from any customer billable event. Never invoice cancelled or failed tasks merely from this local ledger. A verified Studio media authorization API, secure worker isolation, service-to-service transport, and explicit product/pricing approval are prerequisites. Do not accept arbitrary remote URLs or paths for media. No changes to takatak-v1 or live billing in this increment.

## Implemented private namespace precursor
Explicit workspace credentials now select a server-owned namespace, independent project map, per-workspace CSRF token and local usage ledger. No browser-provided workspace ID grants authority. Render status and cancellation check the authenticated workspace. This establishes an application-level isolation baseline for the later verified Studio credential exchange; it does not yet authenticate TAKATAK members or read Studio entitlements. Do not expose publicly or connect to live billing.

## Private gateway verification (receiver-side only)
Optional gateway mode requires the existing private workspace configuration, C4PCUT_GATEWAY_MAPPING_FILE (JSON mapping authoritative lowercase client UUID to preprovisioned workspace slug, one-to-one), and C4PCUT_GATEWAY_KEY_FILE (private file containing a unique random 32-byte key in lowercase hex). No Basic fallback in gateway mode. A trusted issuer must check active membership, create_content permission, Studio flag, and dedicated active C4PCUT entitlement on every request before signing. The receiver checks exact issuer takatak-studio-gateway, audience c4pcut-private-v1, profile/client UUID, permission, c4pcut_active assertion, exact method and raw request target, 30-second maximum validity and single-use nonce. Format: base64url(JSON claims without padding) + dot + base64url(HMAC-SHA256 over the encoded claims). Claim keys: iss,aud,sub,client_id,permission,entitlement,iat,exp,nonce,method,target. nonce is 32 random lowercase hex characters. iat/exp are integer UTC epoch seconds. The gateway forwards one freshly signed assertion per request in X-C4PCUT-Gateway, never to the browser. Browser CSRF checks remain. Gateway must strip incoming assertion headers, use authenticated private transport and relay request bodies faithfully; assertions do not sign body content. Replay tracking is in-memory, so restart loses nonce history; no cross-process protection. Use only one private instance. This is receiver preparation, not live SSO, an issuer, a public reverse proxy, or verified billing. Keep disabled until the actual V1 issuer and secure transport are reviewed and tested.

## Gateway protocol v2 (supersedes v1 above)
Audience is now c4pcut-private-v2. Add mandatory body_sha256 claim: lowercase SHA-256 hex digest of exact forwarded request bytes (empty bytes for GET). Legacy v1 assertions are rejected. Authenticate before reading body, reject ambiguous Content-Length or Transfer-Encoding, spool bounded raw bytes, verify digest before dispatch. One concurrent body staging slot; gateway must use bounded uploads, content length and exact bytes. Replay nonces are persisted transactionally in gateway-replay.sqlite3 under the private data root, expire with the assertion, and are not evicted while valid. Maintain synchronized clocks and preserve this database across restart; no public or distributed service is approved. This does not provide encryption, protect against a compromised trusted issuer, or implement actual TAKATAK entitlement lookup. Actual issuer remains unimplemented.
